# DESIGN.md

技術書ライブラリ / Stack Library のデザイン実装方針です。  
Figmaの土台が既にある前提ですが、CodexがUI実装時に判断を誤らないように、プロダクト思想、トーン、デザイントークン、アクセシビリティ要件を定義します。

---

## 1. デザインコンセプト

メインコンセプト:

```txt
Technical Archive × Developer Observatory
```

日本語での解釈:

```txt
静かな技術標本室。
でも、知識同士は星図のようにつながっている。
```

このプロダクトは、一般的な本棚UIではありません。  
技術書を「収蔵された標本」として扱いながら、技術トピック、読書メモ、実装への気づき、学習ルートが相互に接続された知識地図として見せます。

---

## 2. 目指す雰囲気

UI全体で目指す印象:

- 静か
- 知的
- 精密
- モダン
- スタイリッシュ
- 技術者らしい
- 編集的
- 少し不思議
- 個人の知識標本室のような雰囲気

ユーザーに与えたい感覚:

- 読書ログを眺めているのではなく、自分の技術知識を観測している
- 本を探すだけでなく、技術トピックから記憶や実装へ戻れる
- 派手ではないが、細部が整っていて長く使える

## 4. 日本語ファースト方針

UIは日本語ファーストで設計します。

英語圏SaaSのUIを作ってから日本語を貼るのではなく、日本語の見出し、ラベル、本文、ナビゲーションが自然に見える余白、行間、カード幅、情報密度にしてください。

### 言語バランス

- UIの主言語: 日本語
- プロダクト名: 英語でも可
- 技術用語: 日本語 + 必要に応じて英語
- コピーの温度: 静か、短い、知的
- ビジュアル思想: 国籍に寄りすぎない

## 5. コピーライティング方針

UI文言は短く、説明しすぎない。ただし、状態や指標の意味は曖昧にしないでください。

### Heroコピー例

```txt
Stack Library
技術書を、知識・実装・再読のために再配置する。
```

### セクション見出し例

- 読書中の技術書
- 今掘っている技術トピック
- 最近の読書メモ
- 再読候補
- 実装に使った本
- 学習ルート
- 知識マップ

### 空状態コピー例

```txt

```

## 6. カラートークン

Figma土台がある場合はそちらを優先しつつ、実装上のCSS変数名は以下に寄せてください。

### Figma実装基準

2026-06-26時点のFigma叩き台では、概要ページ `01_概要ページ` を主要な実装基準にします。

- 画面幅はデスクトップ `1440px`、左サイドバー `240px`、メイン領域 `1200px` を基準にする
- メイン領域上部に `72px` のトップバーを置く
- コンテンツ左右余白はデスクトップで `64px` を基準にする
- セクション間は大きく取り、概要ページでは Hero から読書中カードまで約 `120px` の余白を持たせる
- 背景には控えめなグリッドテクスチャを敷いてよいが、本文やカードの可読性を妨げない
- Figma MCPが返すReact/Tailwindコードは構造と寸法の参照に留め、実装ではAstroコンポーネントとCSS変数へ変換する

書籍詳細ページ `03_書籍詳細ページ` は `/books/[slug]/` の主要な実装基準にします。

- デスクトップは `240px` サイドバー、`380px` 書籍パネル、残りを詳細パネルにする
- 書籍パネルの背景は `#161b22`、詳細パネル本文面は `#0d1117` を基準にする
- 左カラムの表紙またはプレースホルダーは `300px × 424px` を基準にし、スクロールバーで幅が削れないようにする
- 左カラム下部には書名、副題、著者、出版社、読了年月、難易度、関連トピックを標本ラベルとして並べる
- 関連トピックは `#accessibility` のような slug ベースの小さなタグとして表示する
- 右カラム上部には `READING NOTES` の72pxヘッダーを置き、その下に `692px × 65px` の `BookSignalStats` 行を配置する
- シグナル行は `難易度`, `実務適用度`, `再読価値`, `概念密度` の4項目を横並びにし、ラベル・ドット・テキスト値を必ず併記する
- `BookSignalStats` は上下の見た目合わせを margin で行わず、65px内で `gap: 6px` の中央揃えにする
- 本文セクションはカード枠を使わず、`// why i read this`, `// insight 01`, `// related books` のようなコードコメント風ラベルと本文で構成する
- 本文は `14px / 22px` を基準にし、`#e6edf3` の読みやすいテキストとして表示する
- 関連する技術書は同じ技術トピックを持つ本から導ける場合は自動接続として扱い、`340px × 96px` 程度の低いカードで2列表示する

ライブラリページ `02_ライブラリページ` は `/library/` の主要な実装基準にします。

- 左サイドバー `240px` の右側に、ライブラリ専用の `1200px` 作業領域を置く
- Figma `64:2` を初期表示の基準にし、フィルターは閉じた状態から始める
- 初期表示では `72px` のトップバー、その下に `68px` のツールバーを置き、タイトル・件数・`フィルター` ボタン・表示切替を同じ行に収める
- 選択中条件がある場合のみ、ツールバー直下に `44px` のチップ行を表示し、個別解除と一括クリアを用意する
- `フィルター` ボタン押下後は Figma `70:2` の `instrument-strip` を表示し、読書状態、難易度、レベル、実務適用度、再読価値を横長のセグメントで扱う
- レベルは `difficulty` を使った `Lv.1` から `Lv.5` のレンジフィルターとし、レンジUIは細いトラックとシアンのノブで表現する
- `instrument-strip` の高さは Figma `70:2` に合わせて `156px` を基準とし、ヘッダー行は `44px` で左右端に `FILTERS` とクローズアイコンを分ける。セグメント領域は `81px` 高で、読書状態 `260px`、その他 `220px` の横長セグメントとして扱う。スクロールバーはセグメント内に重ねず、内容幅が表示領域を超える場合だけ下端に表示する。幅はフィルターUIのinner-widthに合わせ、紫がかったグレーのトラックとサムを同じ `4px` 厚で重ね、サムはドラッグで横スクロールできるようにする
- `instrument-strip` 展開時も一覧領域は `1200px` 幅を維持し、カードグリッドはストリップ下に十分な余白を取って始める
- カードグリッドはデスクトップで3列、列間 `24px`、左右余白 `40px` を基準にする
- ライブラリ用 `BookCard` は幅約 `357px`、高さ約 `364px`、内側余白 `24px`、表紙領域 `160px` を基準にする
- カード下部には `Lv.`, `Imp.`, `Ret.` の小さなシグナルを表示し、視覚バーだけでなくアクセシブルな値も保持する
- この画面では背景グリッドを抑え、暗い面と細い罫線で標本棚の密度を優先する

Figmaから読み取った主要カラー:

```css

  --color-bg-elevated: #121214;
  --color-bg-panel: #121214;

  --color-text: #f5f5f7;
```

### 使用方針

- 蛍光色を使いすぎない
- 色だけで状態を伝えない

### 状態色の注意

読書状態、難易度、実務適用度などは色だけで区別しないでください。  
必ずテキストラベル、アイコン、aria-label、titleなど意味情報を伴わせます。

## 7. タイポグラフィ

### 基本方針

日本語本文の読みやすさを最優先します。  
英語の見出しだけを前提にした極端な字間・細字・小さなラベルは避けてください。

Figma叩き台ではロゴや数値表示に `Instrument Serif`、UI本文に `Inter` が使われています。実装では以下の方針にします。

- ロゴ、Hero見出し、メトリクス数値には `Instrument Serif` を使ってよい
- 日本語本文とUIラベルは `Inter`, `Noto Sans JP`, system-ui の順で読みやすさを優先する
- Webフォントが読み込めない場合も破綻しないフォントスタックを用意する
- 日本語本文には英字見出し向けの極端な詰めや小さすぎる行高を適用しない

### 推奨CSS

```css
:root {
  --font-sans: "Inter", "Noto Sans JP", system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "Hiragino Sans", "Yu Gothic", sans-serif;
  --font-serif-display: "Instrument Serif", "Times New Roman", serif;
  --font-mono: "SFMono-Regular", Consolas, "Liberation Mono", Menlo, monospace;

  --text-xs: 0.75rem;
  --text-sm: 0.875rem;
  --text-md: 1rem;
  --text-lg: 1.125rem;
  --text-xl: 1.35rem;
  --text-2xl: 1.75rem;
  --text-3xl: clamp(2rem, 4vw, 4rem);

  --line-tight: 1.25;
  --line-normal: 1.7;
  --line-relaxed: 1.9;
}
```

### 使用ルール

- 本文は原則 `line-height: 1.7` 以上
- 長文メモは `line-height: 1.8` 以上でもよい
- 小さなメタデータラベルは使ってよいが、可読性を潰さない
- 英字だけの極端な uppercase UI は避ける
- 日本語のカード本文は詰め込みすぎない

```css
:root {

  --space-2: 0.5rem;
  --space-3: 0.75rem;
  --space-4: 1rem;
  --space-5: 1.25rem;

  --space-8: 2rem;
  --space-10: 2.5rem;
  --space-12: 3rem;
  --space-16: 4rem;
  --space-20: 5rem;

```

### レイアウト方針

- 最大幅はページ用途で分ける
- 詳細ページは読みやすい本文幅を確保する
- ライブラリ一覧は情報密度を高めてもよい
- Figma準拠のライブラリ一覧は、`260px` のフィルターレールと3列カードグリッドを基本形にする
- ただし、カード内の日本語本文は十分な余白を取る
- グリッド背景は控えめにする
- 罫線は細く、情報構造を支えるために使う

### 推奨最大幅

```css
:root {
  --container-page: 1200px;
  --container-wide: 1440px;
  --container-reading: 820px;
}
```

## 9. 形状・罫線・影

```css
:root {
  --radius-xs: 0.125rem;
  --radius-sm: 0.25rem;
  --radius-md: 0.5rem;
  --radius-lg: 0.75rem;
  --radius-xl: 1rem;

  --border-hairline: 1px solid var(--color-border);
  --border-strong: 1px solid var(--color-border-strong);
}
```

### 使用方針

- 角丸は使いすぎない。Figma叩き台のカードは `2px` を基準にした硬質な印象を優先する
- カードはやや硬質に見せる
- 影は暗い背景に馴染む程度
- 罫線と背景差で階層を作る
- パネルの立体感は控えめ

## 10. カードデザイン方針

技術書カードはECの商品カードではありません。  
本の表紙を見せつつ、技術標本ラベルのようにメタデータを整理します。

Figma叩き台の `specimen-card` は初期 `BookCard` の視覚基準です。

- カード背景は `--color-bg-panel`
- 境界線は `--border-hairline`
- 角丸は `--radius-xs`
- 内側余白は概要ページでは `32px`、ライブラリグリッドでは `24px`
- 表紙またはプレースホルダーは暗い矩形で、カード内の最上部に置く
- 書名、著者、読書状態、進捗またはシグナルを縦に整理する
- 進捗バーを使う場合も、必ずパーセント値や状態ラベルを併記する

### BookCardに必要な印象

- 収蔵品ラベル
- 技術標本
- 読書状態と知識指標が一目で分かる
- 表紙だけに依存しない
- トピックへの導線がある

### 表示要素

- 表紙
- 書名
- 著者
- 読書状態
- 技術トピック
- 難易度
- 実務適用度
- 再読価値

### 避けること

- 表紙画像だけが大きい商品カード
- 星評価中心
- 汎用的なレビューカード
- 価格や購入導線のような見た目

## 11. シグナル表示方針

このプロダクトでは、一般的な星評価ではなく技術書向けのシグナルを表示します。

### 指標

- 難易度
- 実務適用度
- 再読価値
- 概念密度
- 実装接続度

### 表現方法

- 1〜5 の段階表示を基本にする
- 棒、点、短いメーターなどで表現する
- 必ずテキストラベルを併記する
- 値が未設定の場合は `未設定` と表示する

例:

```txt
実務適用度 4/5
```

アクセシビリティ上、メーターだけで意味を伝えないでください。

## 12. 知識マップの見た目

知識マップは、派手なSFではなく静かな技術星図です。

### ノード種別

- 技術書
- 技術トピック
- 読書メモ
- 学習ルート

### 見た目の方針

- 背景は暗く静か
- ノードは小さく精密
- 接続線は細く控えめ
- 選択中のノードだけ明確に強調
- 過剰なアニメーションは避ける
- 詳細はサイドパネルで読む

### アニメーション

使用する場合は短く控えめにしてください。

```css
:root {
  --duration-fast: 120ms;
  --duration-normal: 180ms;
  --ease-standard: cubic-bezier(0.2, 0, 0, 1);
}
```

`prefers-reduced-motion` を尊重します。

## 13. アクセシビリティ必須要件

アクセシビリティは後付けではなく必須要件です。

### 必須

- 日本語本文が読みやすい文字サイズである
- 十分なコントラストを確保する
- 明確なフォーカス状態を表示する
- 色だけで状態を伝えない
- 状態バッジにはテキストラベルを入れる
- クリック可能な要素を視覚的に判別できる
- 行間と余白を広めにする
- キーボード操作を想定する
- スクリーンリーダーで意味が伝わる構造にする
- 見出し階層を崩さない

### フォーカススタイル例

```css
:focus-visible {
  outline: 2px solid var(--color-accent-cyan);
  outline-offset: 3px;
}
```

### ボタン・リンク

- `<button>` と `<a>` を意味に応じて使い分ける
- ページ遷移は `<a>`
- UI状態変更は `<button>`
- クリック可能なdivは禁止
- aria-labelは視覚ラベルが不足する場合のみ使う
- ariaで意味を隠蔽せず、まずHTML構造を正しくする

## 14. レスポンシブ方針

### モバイル

- 一覧カードは1列
- フィルターは折りたたみ、またはモーダル/ドロワー
- 詳細ページのサイド情報は本文下へ回す
- 知識マップは初期版では簡略表示でもよい

### タブレット

- カードは2列程度
- 詳細ページは本文とメタ情報を上下または2カラムで調整

### デスクトップ

- ライブラリは複数列グリッド
- 詳細ページは本文 + サイドメタ情報
- 知識マップはサイドパネル付き

## 15. コンポーネント別スタイル方針

### ReadingStatusBadge

- 状態名を必ず表示
- 色は補助情報
- `aria-label` またはテキストで状態が分かること

### TopicChip

- トピック名を表示
- クリック可能な場合はリンクとして実装
- 色は `colorToken` を使ってもよいが、可読性を優先

### SignalMeter

- 指標名と値を必ず表示
- 1〜5の視覚表現は補助
- 未設定時は空のメーターだけを出さない

### FilterPanel

- フォーム要素として意味が通るHTMLにする
- ラベルを省略しない
- 選択中条件の解除導線を用意する

### SearchBar

- `label` を持つ
