# Design System Landscape

Use this registry to select evidence for a named Stack Library question. It records all 73 rows visible in the public Design System Collection on 2026-08-01, including the duplicated Cloudscape listing. It is a research snapshot, not a quality ranking or permanent claim of availability.

## Status legend

- `Current`: the canonical public surface was reachable and showed maintained documentation, packages, releases, or recent content.
- `Current / limited`: a public surface exists, but its maintenance or complete design-to-code coverage could not be established from public evidence.
- `Moved`: the listed URL redirects or a newer canonical surface was found.
- `Restricted`: the referenced material is private, sign-in gated, or otherwise not publicly inspectable.
- `Historical`: the listed surface is deprecated, retired, replaced, abandoned, or no longer a trustworthy design-system source.

Recheck the canonical URL, version, repository activity, accessibility claims, and design assets before using an entry in a contract.

## Cross-system conclusions

Across the collection, the strongest current systems connect semantic foundations to components, patterns, content, accessibility, contribution, release, and migration guidance. Mature systems also expose the relationship between design assets and running code rather than treating a Figma library as the system itself.

Apply these conclusions to Stack Library:

1. Treat product principles, content rules, accessibility, tokens, components, patterns, and lifecycle guidance as one governed system.
2. Preserve behavioral traceability among Figma, React, Storybook, and tests; visual similarity or matching names alone are insufficient.
3. Publish migration and deprecation intent whenever a public contract changes.
4. Track source status and last verification. A prestigious but retired or private system is historical evidence, not implementation authority.
5. Select benchmarks by the question being answered: Japanese content, archive/library discovery, accessibility, governance, component API, design-to-code parity, or migration.
